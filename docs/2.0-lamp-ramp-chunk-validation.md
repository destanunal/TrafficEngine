# Traffic Engine 2.0 — lamp, ramp and chunk lifecycle checks

Applied to both Minecraft source trees, 1.20.1 and 1.21.1.

## Rendering and terrain

- The new single-sided vertical lamp lens moves back 0.5 model units to sit against its bezel. A cached shallow octagonal rim supplies side visibility. The eight rim quads use the existing texture batch; there is no added render pass or per-bulb geometry allocation. Legacy double-sided/horizontal lamp placement is retained.
- Traffic lamps' environmental RGB emission strength changes from 4 to 3. Lens emissivity and other light categories are retained.
- Sloped pedestrian railing detects signed support differences (up to one block), including descents and level/slab-to-ground transitions. Existing positive-rise states remain valid. A descending property and zero-rise profile represent the missing cases.
- Terrain updates are event-driven: changing a layered surface checks at most 12 neighboring positions and schedules a single recalculation for relevant railings. Shape/collision lookups read no terrain and use bounded tables. No new block entity or recurring terrain ticker is added.
- Descending model aliases reuse the same physical profile where model bounds require it; black assets inherit the gray geometry. The inventory-only transform now has a 30-degree roll, with calculated centering. Hand transforms and item/world mesh coordinates are unchanged.

## Chunk lifecycle / compatibility

- EmissiveVertexConsumerMixin interface injection handlers are public concrete default methods. Their descriptors preserve the respective Minecraft API signatures.
- ColoredBlockEntity.setRemoved no longer refreshes road meshes or looks up neighbors. LevelChunk.clearAllBlockEntities iterates its entity map while invoking removal; neighbor lookup from this callback could insert entities into the map being cleared.
- LoadedRoadData reads already loaded chunks and existing entity maps. It does not instantiate missing block entities or wait for server chunk loads. Road rebuild/color paths skip removed entities.
- The optional JourneyMap adapter caches its reflective accessor once per API class. Map workers use existing road entities and stored mesh coverage instead of constructing entities or scanning/tessellating neighboring roads. No hard JourneyMap dependency is added.

## Verification

- compileJava passed: common/Forge/Fabric for 1.20.1; common/NeoForge/Fabric for 1.21.1. Packaging tasks were explicitly prohibited by the compile-only init script; no JAR was produced.
- Per version: 24,603 native railing/gate/terrain checks, 4,608 railing states, 864 shared outlines, ascent/descent/level across all layer pairs and directions. 23,040 repeated shape calls performed zero world reads (about 2–3 ms in this isolated run; not an FPS measurement).
- Per version: 185 checks including the real LevelChunk.clearAllBlockEntities callback with 64 colored entities, missing/removed entity lookup, compiled interface handler access flags, rim normals/winding and depth.
- Minecraft's own JSON model deserializer accepted 217 railing/item models per version. 64,080 combined checks cover state-model matching, support heights, model bounds and UVs. Non-GUI item data was compared against the prior validated revision.
- The GUI angle was inspected in a static geometry render, not a game screenshot.

## Limits

These are source/compile/native regression results, not an in-game multiplayer or full-modpack reproduction. The known unsafe removal path and interface compatibility defect are fixed, but the reported host window freeze is not established as resolved. A thread dump during an actual freeze and the matching host log are needed to distinguish chunk generation, server-thread blocking, memory pressure and other mods. Installed modpacks, saves and their existing Traffic Engine 1.9 JAR were not modified.
