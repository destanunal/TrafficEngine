# Traffic Engine 2.0 — final optimization and visual validation

Date: 2026-10-26. Applies to the local 1.20.1 and 1.21.1 source trees.

## Changes in this pass

- Vertical and horizontal countdown renderers now bound their phase maps at 16,384 entries and their per-signal maps at 4,096 entries. Access order keeps recently used signals. These are learned timing caches, not saved controller settings. An evicted inferred duration can be learned again on a later cycle.
- Countdown phase key strings are built lazily once per entity/face/level and reused. The legacy horizontal `dimension_position` and vertical `dimension_position_face` formats remain compatible. Front/back timers remain independent. A small helper retains no world/entity references.
- Remaining countdown time is evaluated once per rendered signal instead of twice. The last-lit boxed timestamp is replaced only when the game tick changes. Known-duration lookup uses one map read. Existing blink hold, calibration and coalesced persistence behavior are retained.
- RGB lighting allocates its dirty-position map only when a source changes/removes. With no registered sources it returns before making an iterator or dirty map. The existing 2,048-source cap and eight-volume-per-tick rebuild budget are unchanged.
- The exact duplicate powered request-button model inherits the active model while preserving both resource identifiers. Output processing removes only vanilla model element `name` editor metadata. Sources, credits, textures, fonts, translations, display transforms, custom face metadata and custom-loader models are preserved. Existing JSON minification and maximum ZIP compression remain in place.

- Terminal corner is a rounded radius that joins a short vertical support. Both original connection coordinates and all six saved assembly cells remain unchanged.
- The curved mast uses the existing sign-pole texture and straight-facing shade metadata to stabilize directional banding. It remains normally scene-lit, not emissive. This reuses the existing terrain shading hook; optimized third-party terrain renderers still need in-game visual verification.
- Mesh: 33 offline-authored segments, 134 faces (previously 120). New rounded tip adds 14 static faces. No block entity, custom renderer, recurring tick, rendering-time mesh generation or added render pass. Closed topology: 268 edges, each incident to two faces. Maximum adjacent segment direction change is 15 degrees.
- Cached selection/collision bounds reduced from 84 to 47, with 24 shared shapes across six parts/four facings. The empty saved helper cell remains pickable. Water states share the same shapes.
- A hanging horizontal lamp's carrier stops at the clamp rather than protruding below the housing. A lower-post mount retains its lower connection and ends at the opposite clamp. The new `bottom_support` property defaults false so previous hanging states retain the upper mount. Attachment detection only runs at placement/vertical neighbour edits; 48 shared mount/model/facing shapes are reused. Rendering and shape queries do not inspect terrain.

## Teleport/window-freeze report

The user's new summary of three freeze dumps points to Traffic Engine 1.9's `ColoredBlockEntity.refreshRoadMeshes` during chunk packet replacement, alongside repeated `ConcurrentModificationException`. This is consistent with the unsafe removal callback already fixed in the local 2.0 trees:

- `ColoredBlockEntity.setRemoved()` calls only the base removal callback; it does not refresh neighbouring models.
- `LoadedRoadData` reads already loaded chunks and existing block-entity maps, instead of creating missing entities through `Level.getBlockEntity`. Server lookups use `getChunkNow`; client lookups use `create=false`.
- Removed entities are skipped by road lookup/rendering paths. Neighbour refresh remains available for actual road-data changes.

This pass reran the actual Minecraft `LevelChunk.clearAllBlockEntities()` method on a map of 64 coloured entities attached to a minimal client world. It completes, clears the map, marks every entity removed and never calls a model manager or mutates the iterated map. Missing lookups do not add entries, and removed entities are not returned. Interface mixin handlers were also checked to be public concrete methods.

The new ZIP itself was not supplied in this turn; its reported contents are user-provided evidence. The installed 1.9 modpack was not replaced. Passing the isolated regression is not proof that every freeze in the full modpack is resolved. Confirm with the host's actual modpack and matching freeze captures after installing an explicitly requested 2.0 artifact.
