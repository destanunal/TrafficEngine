## Implemented

- Normal, sloped and gate railings accept every paintbrush dye. Wrench color cycling is removed; manual slope selection remains available. Painting stores one color value in a block entity with no ticker or custom renderer. Existing gray/charcoal states remain readable.
- Paintbrush pattern categories are stored per stack. Packets that do not edit a category preserve the existing category.
- All three road sign sizes support diagonal placement and hanging placement beneath curved pole sockets. Integral carriers stop at the rear support unless an actual upper connection continues them. Curved pole stems and end sockets accept compatible connections.
- Large sign arrows increase in size for one- and two-line layouts.
- Sign faces use convex planar strips in place of degenerate fan quads. Border rendering uses separated layers, increased artwork clearance and constant depth bias to address distance and movement artifacts.
- The optional Sodium RGB handler applies color to ordinary full-bright terrain while preserving its existing brightness and skylight. Self-emissive materials remain excluded.

- Railing tint values match the canonical dye RGB values. Paintbrush left-click clears railing paint; normal, sloped and gate variants use the same erase path.
- Git whitespace validation was unavailable in this environment: Git diff reported that the checkout was not a work tree.

## Limits

These are compilation, resource and native logic checks. They do not verify live mixin application or visual output with OptiFine/Sodium/LambDynamicLights. In-game checks remain necessary for distance artifacts, diagonal mounting and visible paint colors. No FPS benchmark was taken and no zero-impact performance claim is made.

No packaging task or trial/release JAR was produced. No release was published.

## 2.1.1 visual and lighting follow-up

- Compact road boards use one centered rear spine. Medium and large boards have symmetric quarter-width spines and two rails at 23% and 77% of panel height. Straight/diagonal, freestanding, mounted, connected and hanging variants share the existing sign metal texture, physical UV scale and shading metadata. Connected large boards retain the upper carrier continuation.
- Hidden brackets are excluded from road-board selection shapes, removing their tiny central targeting edges. Variable-speed board selection geometry is preserved.
- Curved-arm parts 4 and 5 accept sign mounting on every horizontal side. End-socket hanging placement is retained.
- Creative-tab road boards remain ordered small, medium, large. Their inventory models now use one physical GUI scale, so the size differences remain visible. All projected vertices fit inside a 14.4-pixel area of a 16-pixel slot.
- Three-row 4x3 signs use an 18% larger arrow size. Four-row arrow size is preserved.
- Brush erase has a dedicated, reach-checked server action and bypasses vanilla mining cracks and creative breaking. Railing packets explicitly include NONE on erase and apply texture/tint changes together. A gray metal state ignores stale dye; a pending dye packet uses neutral gray rather than charcoal. No new recurring ticker or custom railing renderer is introduced.
- LED RGB volumes are confined to the front half-space for every facing. Forward intensity and opaque-wall blocking are preserved. Other light sources retain omnidirectional propagation. The half-space check runs only when a source volume is rebuilt; terrain rendering adds no world reads or ray casts.

Follow-up validation uses compileJava only, with `-x :common:jar` and the compile-only init script to exclude the common JAR dependency. No packaging or game artifact is required. Targeted checks cover all sign states, cached shape lookups, curved-arm sides, dye save/load/tint behavior, hardware geometry and GUI extents, plus four-direction LED propagation and wall blocking. In-game appearance and FPS have not been measured.

Follow-up checks passed on both Minecraft versions: common and both loader compileJava tasks; 5,604 native assertions across 1,024 sign states; 102,400 cached shape lookups without world reads; four-direction LED propagation and opaque-wall blocking; and 24 sign models / 1,172 nondegenerate hardware faces with diagonal parity and GUI bounds. The final maximum selection outline has 72 edges. A maximum-strength directional source visits 2,255 cells per facing versus the unchanged 4,089-cell omnidirectional bound. Git diff --check passed. No JAR was produced.
