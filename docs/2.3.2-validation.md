# Traffic Engine 2.3.2 validation

## Implemented behavior

- Blueprint default remains strict empty-area placement. Existing four horizontal direction values retain their meaning; values 4/5 add Up/Down. Spacing accepts 0..32 and copies remain 1..32. Rotation stays horizontal.
- A single localized placement-policy control cycles strict / skip occupied / replace. Replacement targets the clicked cell; skip and strict target the clicked face. Client preview and server use the same anchor rule. The material dropdown documents its maximum estimate; the server charges only cells actually written.
- Replacement refuses unbreakable blocks, unsupported block entities/containers and incomplete old or new multi-block assemblies. Existing permission, reach, loaded-chunk, border, entity-collision and loader placement/break cancellation checks remain. No target chunk is loaded on demand. Failed copies restore touched cells before any material charge.
- Undo keeps previous blocks and supported device data alongside the ownership snapshots of the newly placed copy. Undo checks that placed states/data are unchanged before restoring the previous contents and refunding construction materials. Replaced blocks produce no drops, preventing duplication on undo. Existing bounded history/expiry rules apply. Empty originals are omitted from retained history; entirely skipped copies do not update inventories or erase the previous undo operation.
- The first flat cell of the curved arm (part 4) now accepts lower posts, traffic/warning lights, regular signs, directional signs and suitable hanging LED devices, like part 5. The optional socket follows the actual slightly curved underside; covered underside faces and hidden socket caps are omitted. Geometry uses the normal traffic sign post texture and one texel per model unit. It reuses the existing neighbour-derived support flag and coalesced integrity tick, with no new block entity, repeating tick or scan.
- Warning lights now retain their eight-way placement. Settings packets preserve the diagonal flag and the lit lens follows the same transform. Picking/collision shapes include the front lens and follow the actual warning housing, rather than a normal traffic-light case. Selection uses two cached oriented frames and diagonal hit/break particles reuse the straight state.
- New controls have English, Turkish and German captions. Existing cached glyph-bound centering and font/language reload invalidation are reused.

## Limits and unconfirmed report

This is headless validation. In-game visual inspection, full server-world replacement/undo with third-party protection mods, shader compatibility and FPS measurements have not been performed. Placement/undo retains its existing bounded queue, maximum 512 cells per copy / 4096 repeated cells, and bounded history memory. No zero-FPS-impact claim is made.

The separate missing-sign-text comment was checked quickly as requested: the current directional-sign screen saves on Esc as well as Save, except explicit Discard; destinations and arrows share the update packet. No confirmed cause was found and that text/render path was left unchanged pending the reporter's version, sign type and render-mod details.

## Warning mount and interface follow-up

- Warning housing rotates independently of its square stem. Both bottom and upper stems are two model units tall with normal traffic-post texture density/phase; covered end caps are omitted. Housing depth is three units so a diagonal head fully seats over the square carrier.
- An upper ordinary/curved post selects hanging placement on placement or an upper-neighbour update. Removing that support restores the short lower stem. The update uses the supplied neighbour and adds no scan, block entity ticker or recurring task.
- Baked off lenses, animated glow, collision/picking and two-frame oriented outlines follow the same housing offset. Each finite shape is built once; outline arrays reuse the existing bounded cache.
- Warning destruction retains one quarter of generated straight-state particles for both normal and diagonal placement. The regression executes the actual Mixin filter and checks that its temporary reduction does not leak into unrelated effects.
- Traffic-light configuration preferred dimensions are 440 x 310 (previously 470 x 330). Responsive forms, scrolling and cached localized glyph-bound centering remain in use; no additional measurement/cache path was introduced.
- Blueprint appearance is a native baked clipboard with a simple floor-plan face, using existing vanilla and post textures, 15 elements / 25 faces. No custom item renderer or new texture atlas allocation is needed. Its projected GUI silhouette is approximately 11.34 x 15 pixels, within a 16 x 16 slot. A software mesh preview was inspected; this is not an in-game screenshot.
- Four platform compileJava tasks and both common checks pass. Asset checks cover all 128 warning blockstate combinations, 2-unit unrotated stems, model/outline bounds, glow alignment/depth separation, UVs and existing curved socket joins. The legacy straight warning geometry check also remains supported.
- Warm geometry/outline allocation sampling uses 250,000 paired lookups per branch. Both branches most recently recorded 584 bytes total across 250,000 paired lookups (constant sampling/JIT overhead, no allocation scaling per lookup); this is not an FPS benchmark.

## Chevron alignment, short horizontal warning mounts and curved texture follow-up

- Chevron boards now rotate only the panel/rear bracket. Their lower 2 x 2 carrier stays aligned with a normal traffic sign post in both single and triple-board layouts. Cached collision/picking shapes and the simple two-frame outline follow that split. Breaking particles retain the straight-state shape.
- Covered chevron stem caps are omitted. Only the small exposed top corners are drawn, clipped against the rotated panel and rear bracket, with ordinary post planar UV scale/orientation. Zero-area faces are discarded.
- Above/below a horizontal sign post or the fully straight curved-arm end, warning heads move seven model units toward the actual arm surface. The existing two-unit short stem remains, and the support omits its redundant half-block branch/socket. The slightly inclined first arm cell keeps its fitted socket to avoid intersecting a flat connector with its underside.
- Existing warning block entities schedule one server-side reconciliation on chunk load, updating the state only when required. No block-entity ticker or recurring task was added.
- Compact warning heads reuse the existing nearby lamp block-entity candidate cache for accurate targeting outside their owning cell. The visual hit remains on the head, interactions retain the correct owning block and nearer walls remain authoritative. No additional terrain/chunk scan was introduced.
- Native post model selectors omit duplicate connection arms while preserving the previous geometric union for all 192 axis/connection combinations. This removes overlapping arm geometry and redundant baked faces.
- Curved mast faces now use the normal post texture at one source texel per model unit, with continuous surface-distance UV coordinates. Flat upper/lower surfaces match the ordinary horizontal-post mapping. Faces split only at texture wrap boundaries; existing smooth shading and normals are retained.
- Final checks per branch: 2,625 equipment/mount/cache/picking assertions, 37,904 asset checks, 2,457 additional mast/chevron/post-selector model checks, 120 shared curved-mast corners checked in four facings, and the existing placement/model clearance check (98 mast faces). Both common compileJava tasks and all four loader compileJava tasks passed. The final loader validation explicitly excluded common:jar and guarded against packaging tasks.
- The most recent allocation sample was 584 bytes total across 250,000 paired warm shape/outline queries per branch. In-game screenshots, frustum-boundary behavior and FPS were not measured.
