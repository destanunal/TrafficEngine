# Traffic Engine 2.0 — railing gate, ramp panels and single-sided lamp model

Applied to Minecraft 1.20.1 and 1.21.1. No packaging or trial/release JAR tasks were run.

## Player-visible changes

- Added Pedestrian Railing Gate, using the same posts, handrail, vertical pickets and gray/charcoal palette as Pedestrian Railing. Right-click opens/closes one hinged leaf. Wrench changes color. Redstone power edges open/close it. Gate collision is empty while open. Soft built-in iron trapdoor sounds are used.
- Added Sloped Pedestrian Railing as a separate connecting piece. Placement inspects the immediate supported terrain to choose one of eight 1/8-block grades. Shift + wrench cycles grade; wrench changes gray/charcoal. Its lower end joins the flat railing, and the full sloped span terminates at the raised post without adding an overlapping flat arm at the high end.
- Flat railing now anchors to the height of Traffic Engine road/curb/sidewalk layers. Stacked flat railing inherits that offset. All existing up/down joins and color-specific particles remain.
- Both pieces appear immediately after the existing railing in the creative inventory. Recipes, reversible flat/sloped conversion, loot tables and tool/connection tags are included.
- Per-bulb pencil hover text is simply “Özel Çizim Ekle” / “Add Custom Drawing” / “Eigene Zeichnung hinzufügen”.
- Only the single-sided vertical lamp family was restyled: narrower beveled gray shell, recessed charcoal face, slim rain hoods and rear cover. One-to-four lamp variants, diagonal variants and the inventory preview use the new geometry. Signal planes, masks, schedules and rendering code remain unchanged.
- The double-sided lamp's former shared front-body references were isolated into exact legacy-front resource copies. Its existing front/back appearance and item model were preserved. The horizontal lamp was also left for later visual approval.

## Runtime design

- Gate/ramp/flat railing changes add no block entity, ticker, per-frame world scan or animated renderer. Opening and terrain/connection changes use block state events.
- Gate: 64 states share eight outline shapes. Closed/open collision uses vanilla fence gate behavior.
- Ramp: 2,048 states (including color/water) share at most 512 outline and 512 collision entries. Hot shape lookups only index these bounded arrays. Placement/support/connection checks inspect immediate neighbors rather than searching a region.
- Flat railing: bounded 8 × 16 shifted outline/collision tables; color and vertical connection flags share geometry. Static multipart model sharing is retained.
- Gray/charcoal model variants inherit geometry where applicable, reducing repeated resource data. Vanilla JSON rail slopes use fine static segments; no arbitrary-angle loader or render hook was introduced.
- Main vertical body element counts, old → new: one lamp 9 → 12; two lamps 15 → 16; three lamps 20 → 19; four lamps 27 → 22. No new world rendering pass was added. This is geometry accounting, not an FPS measurement.

## Validation

- Latest `:common:compileJava` passed on both Minecraft versions. Existing Mixin/deprecated API warnings remain.
- `RailingGateSlopeCheck`: 10,491 assertions passed per version against the compiled Minecraft classes: all gate/ramp states, open collision, gate connection orientation, color/water cache sharing, all layer offsets, stacked offsets, automatic 1/8 and full-block grades, and rotation.
- In that standalone process, enumerating the complete cold ramp shape/collision set took about 0.96–1.00 seconds. 10,240 already-cached outline lookups took about 0.9–1.3 ms with zero world reads. These measurements include a synthetic complete state sweep and are not in-game FPS/frame-time benchmarks.
- Resource validation: 227,652 assertions across both versions. Checks cover authored cuboid/UV bounds, model/texture references and inheritance, every gate/ramp state selector, the short Turkish tooltip, and preservation of all eight old double-front model resources apart from line endings.
- A static preview was rendered directly from model geometry and visually inspected. It is not an in-game screenshot and does not reproduce Minecraft lighting/materials exactly.

## Remaining visual/game checks

- Check the new shell in-game with body dyes, one-to-four bulbs and diagonal placement before extending the design to the double-sided lamp.
- Check gate interaction/Redstone sounds and flat/graded railing placement in a game world, including ends at chunk boundaries and unusual support arrangements. Native state/shape checks do not replace those interaction tests.
- Automatic support adjustment targets Traffic Engine's layered road/curb/sidewalk blocks. Grade can be chosen manually for other arrangements; universal third-party ramp detection is not claimed.
