# Structure Blueprint Tool — 2.3

## Usage

1. Obtain the Structure Blueprint Tool from the Traffic Engine creative tab, or craft it using three paper, lapis lazuli, an iron ingot and redstone (two rows: PPL / PIR).
2. Right-click two corner blocks. The server captures a valid selection automatically on the second click and enables placement preview; there is no save/delete/name step.
3. Right-click in the air for rotation, repeat direction, gap (1–32 empty blocks, default 8), copies (1–32), the plan thumbnail and the upper-right material list.
4. Gap is the number of empty block cells between occupied structure footprints, measured in the repeat direction after rotation. For a one-block object and Gap 4, successive anchors are five blocks apart. Wider structures add their occupied width; air padding in the original selection is excluded. Preview and server construction use the same calculation once per layout/job.
5. Right-click a block face to construct the preview. The server checks permissions, collision, reach and materials, including loader placement-cancellation events. The existing 4096-block total bound applies.
6. Shift + right-click clears the selection and its automatically captured plan. Select area does the same before returning to the world. Repeat settings and undo history remain available.
7. Keep the tool in either hand until construction finishes. Undo removes the most recent build and refunds consumed items under the existing guards. Creative placement is free.

## Automatic plan data and bounds

- One plan per physical tool; persisted in item NBT/custom_data. No unbounded global blueprint library or dimension references are retained by idle tools.
- Source bounding box: at most 16×16×16; up to 512 non-air blocks per plan. At most 4096 target blocks and 32 copies per build. Up to 192 KiB of blueprint tool data.
- The initial placement anchor must be within 10 blocks. Every target must remain within 128 blocks of the player, inside the world border and in already loaded chunks. No chunk-loading scans.
- Target block cells must be air. Terrain, containers and existing builds are never deliberately replaced. Player/entity collision is also checked by the server.
- Ordinary block states and supported Traffic Engine sign text/textures, colors, lamp schedules, signal/controller settings and LED data are saved. Inventories, block entities outside the supported Traffic Engine types, entity passengers/mobs, fluids and indestructible/no-item blocks are excluded. Unsupported data aborts capture instead of silently stripping contents.
- Curved poles, doors, beds and display helper cells must be selected in full. Free helper cells require their paid master; double slabs and snow layers have corresponding item costs.
- Device links inside the selection follow rotation, changed display master anchors and each repeated copy. External or cross-dimension links are detached, rather than retaining control of the source build.

## Runtime design

- Preview meshes are cached per rotated state and shared between repeated copies. The vanilla selection buffer is reused; no ghost entities or extra terrain rendering passes.
- Item component identity avoids copying/decoding tool NBT on idle ticks. Wireframes are rebuilt on plan/settings changes and released on tool/world/resource changes.
- Conflict colors update at most once per four client ticks after the target or relevant blocks change. Idle previews do not rescan blocks; a bounded list of chunk availability flags is checked once per second.
- A global queue processes one complete copy (up to 512 cells) per server tick, capped at eight jobs and one job per player. Complete copies remain atomic so multi-block integrity checks cannot observe a half-placed curved arm. Per-copy material checks and protection hooks run on the server thread.
- Text uses existing Traffic Engine centered button/slider captions and reload-aware glyph measurement caches. English and Turkish strings are provided; other locales use the English fallback.

## Validation

- Minecraft 1.20.1: common, Fabric and Forge compileJava.
- Minecraft 1.21.1: common, Fabric and NeoForge compileJava.
- Headless production-code tests cover palette corruption/limits, normalized rotations and inverse transforms, material counts, internal/external/cross-dimension link remapping, all complete display footprints and master reanchoring, curved assembly integrity, preview mesh sharing, relevant-only invalidation and resource-cache clearing.
- Existing 2.2.1 terrain, ceiling mounting, shape cache and particle regressions were also checked.
- These checks do not replace live client/server, third-party claim-mod or shader testing. FPS/heap improvements have not been measured in a running game. No release packaging or publishing was requested.

## Undo

- Undo cancels pending repetitions and removes the last blueprint build, validating unchanged block states/data, reach, dimension and native break protection hooks. It returns the exact item stacks consumed by each removed copy, including custom data; no breaking particles or extra block drops.
- One complete copy (up to 512 cells) is removed per server tick, sharing the placement budget. Completed copies are refunded once; changed or protected remaining copies are preserved.
- One operation per player for ten minutes, at most eight cached players, 512 KiB per operation and 2 MiB total idle history. Oversized builds remain valid but are not retained for undo. History is transient and cleared when the server stops. No idle world scans.

- Compact native menu uses a plan card and a two-column placement card. The size/total row and bottom usage text are removed. Only the localized selection-reset shortcut appears in the item tooltip (English, Turkish and German). Both repeat limits are shared by UI, saved-data clamping and server packet validation; the existing 4096-block work budget is retained.
