# Traffic Engine 1.9.1 implementation and validation

## Changes

- Curve Direction Signs support eight placement directions. Cardinal wide boards retain automatic joins; diagonal boards are standalone. Sixteen outline shapes are cached.
- Common menu buttons, edit fields and slider captions use visually centered text. Drawing tools use compact icons.
- Custom road stencils can be saved as client favorites (128 maximum, persisted separately from world data). Existing Shift + right-click stencil copying is retained.
- The road/signal-mask editor, LED editor and sign workbench support adjustable pencil/eraser sizes and canvas mouse-wheel input. Footprints are clipped to the canvas; continuous strokes do not bridge a pointer excursion outside it.
- Hydraulic Bollards have wrench and Redstone control. Power retracts them; removing power raises them. Eight scheduled two-tick steps run only during movement. There is no block entity or idle ticker.
- Pedestrian Railings use vanilla cached fence connections. Wrench switches black/gray; both colors share collision/outline caches. No block entity is added.
- The pedestrian request button has a modern yellow/black body and static English, Turkish or German display sprite selected during model reload. Unsupported locales fall back to English. Four small 64x96 PNGs include the default fallback; no world-text renderer is added.
- Lit traffic-signal lenses use a cached emissive material. Terrain color adapters cover the legacy Sodium/Embeddium pipeline and the Sodium 0.6/0.8 FRAPI pipeline, preserving incoming dynamic brightness and sky light. No additional terrain render pass or mandatory dynamic-light dependency is added.
- RGB source registration is capped at 2,048. Propagation skips unloaded client chunks. Existing processing is limited to eight changed source volumes per client tick. Maximum open-air strength-15 propagation visits 4,089 cells, with 4,088 block-state reads; warning-light volumes have a smaller radius.
- Legacy sign conversion runs at most once after a level is available, without spawning waiting threads. PNG size/header checks precede native decode; zlib work has a 1 MiB expansion limit and always releases native state.
- Existing legacy block palettes are remapped only when a replacement exists. Invalid Traffic Engine block entities at mismatched block states are skipped before construction. Multipart definitions share their state-aware baked models.

## Validation (2026-10-24)

- `:common:compileJava`, `:fabric:compileJava` and `:forge:compileJava` (Minecraft 1.20.1): PASS.
- `:common:compileJava`, `:fabric:compileJava` and `:neoforge:compileJava` (Minecraft 1.21.1): PASS.
- Loader compilation uses compiled common classes with `:common:jar` excluded. No release/test mod JAR or full packaging task was run.
- Actual screen input checks: pencil/eraser selection, continuous drawing, outside/re-entry behavior, per-pixel color and wheel-resized 3x3 footprints: PASS on both versions.
- Standalone production-class checks: cached equipment geometry, diagonal mirror/rotation, legacy block/entity loading, brush clipping, color channel order, compressed data bounds and PNG header bounds: PASS on both versions.
- Custom favorites: persistence, preset aliases, duplicate rejection, removal/replacement, 128-entry cap and preference-file size guard: PASS on both versions (isolated scratch config with a test-only Minecraft directory stub).
- Actual native vertex buffers accept complete lit/off signal geometry and the emissive vertex layout: PASS on both versions.
- Source assets: 31 new/replaced models per version, 256 sign model combinations, all railing connections, nine bollard heights, outward cylinder winding, texture references and crafting recipes: PASS.
- RGB volume check: bounded traversal, independent-channel merge, immutable snapshot publication, source removal and preservation of dynamic/sky brightness: PASS.

These checks are not an in-game FPS measurement or a full modpack compatibility test. Optional Sodium hooks were checked against the official source signatures. Runtime integration with LambDynamicLights and Sodium/Embeddium Dynamic Lights still requires the user's installed mod versions/modpack.

## Reported 130-mod pack crash

The supplied 1.21.1 report shows `OutOfMemoryError: Java heap space` with an 8 GiB heap. The last allocation is in creative-tab contents while multiple mods wrap that path. This does not establish which mod retained the heap, nor prove that Sable or Sinytra caused it. The separate old invalid-block-entity log and the heap crash are distinct observations.

The safe load/cache limits above address identified risks. The memory crash is **not confirmed fixed**: the custom modpack has not yet been shared, so reproduction/retained-heap diagnosis remains pending. Unknown removed legacy blocks are not assigned invented replacements.

## Standalone check sources

`docs/checks/Update191RegressionCheck.java`, `DrawTool191Check.java`, `Bulb191Check.java` and `LightVolume191Check.java` run against compiled common classes plus the mapped Minecraft/dependency classpath. Use `javac -proc:none` and a disposable working directory; they do not package the mod or modify a game world.

`Favorites191Check.java` additionally uses `fixtures/net/minecraft/client/Minecraft.java`, compiled only into an isolated test classpath, with `-Dtrafficengine.scratch=<temporary-directory>`. Never put that stub in the mod's sources or a real game classpath.

For compile-only loader verification, pass `-I docs/checks/compile191.init.gradle -x :common:jar` to the appropriate `compileJava` tasks. The init script refuses packaging tasks.
