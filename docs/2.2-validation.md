# Traffic Engine 2.2 validation

## Implementation

Selection geometry uses the existing line buffer. Equipment outlines use the bounded block-state cache. Ground features and curved masts share a 64-entry LRU mesh cache with model identity checks and resource-reload invalidation. Mesh extraction/welding is cold work; warm rendering performs silhouette tests and emits existing line vertices, without world scans or a separate pass. Water and unused mast socket states are normalized. Invisible auxiliary mast cells reuse the known part-0 model with a fixed local offset, without neighbour reads.

The earlier Forge hook caused the reported AnalyzerException/NPE during primitive-array local-table reconstruction. It is replaced by ModifyExpressionValue on getShade(FFFZ), capturing the original process arguments directly. NeoForge also avoids array-local capture. Physical normals and lightmap sampling are untouched. Curved shade weights are normalized/baked once; hot shading uses arithmetic and directional shade values, with no arrays, normalization or trigonometry allocated per face/frame. Rigid diagonal equipment retains its ordinary-placement reference; bends use continuous weights to avoid the previous abrupt cardinal-direction band.

Square sign collars are clipped in authored model space to the diagonal plate's rear plane, keeping a clear square opening around the pole. The eight collar groups still emit 48 quads per sign model. No geometric clipping is performed at runtime.

Inventory checks use the actual Turkish item names, rather than assuming historical source IDs describe their current labels. Both icons retain their right-facing rotation, centering and slot bounds.

Particle normalization returns interned normal states before mesh, sprite and count selection. It covers chevron panels as well as the previous angled equipment and preserves non-diagonal properties and existing reduction tags.

## Checks

- compileJava for common and supported loader modules in both Minecraft projects.
- Update22Check exercises 5,288 states, including all chevron and curved-mast states, unchanged picking volumes, normal particle states, cache sharing and clipping. Authored mast models (including auxiliary cells) are checked against silhouette budgets.
- Platform22LightingCheck uses each actual loader's calculateShade formula to check every cardinal endpoint and continuous bends through the old 45-degree discontinuity in ordinary and constant-ambient dimensions. It verifies the expression target owner/descriptor and rejects primitive-array ModifyVariable hooks. This is not a complete live client startup test.
- Forge 1.20.1 Mixin22Smoke applies the actual installed Mixin + MixinExtras engine to the real QuadLighter bytecode. The new shade method is injected and the former array-local method is absent; the transformation passes without AnalyzerException. The isolated service/configuration lives only in the regression output and does not change production resources.
- Polish211Check checks native plate bounds, pole UV mapping, unchanged picking shapes and warm shape lookups.
- Placement22ModelCheck checks every collar face against both the plate-back plane and pole opening, mast shade metadata, correct icon order/size, rotation, centering and slot bounds.
- SignSupport211Check retains road-board support, UV and GUI-slot checks.

No JAR/package was produced. Full client startup, in-game appearance, FPS and total game RAM are not measured by these checks; isolated Forge Mixin application is verified as described above.

## Double-sided signs and inclined pedestrian railing follow-up

DoubleSign22Check checks all front/back shape pairs, cardinal facings and straight/diagonal placements against both plate-back planes, pole clearance, unchanged plate/post assets and a non-increasing quad budget. The static model path is specific to double-sided signs, with no new render-time filtering or clipping.

DoubleRail22Check exercises the actual particle-retention handlers, unpainted-to-painted support transitions in both directions and the cached railing outline against authored model vertices. Picking/collision shapes remain unchanged. Support-height invalidation ignores paint-only replacements but still responds to actual layer changes. The incline frame is built on cache misses and uses the existing selection buffer.

Follow-up result: compileJava passed for common and supported loader modules in both projects. DoubleSign22Check passed 1,152 assembled combinations. DoubleRail22Check passed 285,801 assertions, enclosing 93,696 authored railing vertices and verifying the actual particle-retention handler. Update22Check also passed for both versions. No full client launch, FPS measurement or JAR packaging was performed.
